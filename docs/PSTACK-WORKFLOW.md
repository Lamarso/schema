# P-stack workflow profile — schema

This is the business adaptation of Lauren Tan's P-stack. Read the existing role/runbook first. Current owner instructions, standing authorizations, deterministic guards, store/account scope and configured model/tools remain authoritative. This workflow supplies a work method, not a new operational permission.

Role: Develop the static planning user interface.

For substantive work, define an observable acceptance, inspect relevant source/state, make a bounded change, verify the real outcome and report evidence plus limits. Keep small routine work small. Do not ask an agent to self-certify improvement; use the actual artifact, fixture, receipt or platform result.

Acceptance for this role: The changed user journey works in a real rendered preview with the intended input/state, readable layout and preserved data handling; static syntax alone does not prove the journey.

Load only the needed selected modules:

- `pstack-business` — `.claude/skills/pstack-business/SKILL.md`
- `pstack-engineering` — `.claude/skills/pstack-engineering/SKILL.md`
- `pstack-content` — `.claude/skills/pstack-content/SKILL.md`

Engineering applies to code/tooling changes; state-model applies only when consequential transitions/retries/concurrency are being changed. Content and metrics apply only to the relevant deliverable or measured claim.

Existing verification recipe: No repository test/build harness is declared; use a local isolated browser preview for authorized UI changes and label unrun checks honestly.

These commands are a runbook, not a claim that they passed in this proposal. Inspect prerequisites and side effects before running unfamiliar checks. Do not perform a live listing, send, ad launch, refund or paid model call to test skill installation. Existing authorized operations retain their established controls.

Runtime/source status: see `docs/PSTACK-DEPLOYMENT.md`. Keep local installed, repository proposed, runtime registered and production verified distinct. If a skill file is unavailable in a managed runtime, use the bounded inline domain instructions in its real prompt; do not claim local autodiscovery applies there.

Provenance and license: `.claude/skills/PSTACK-PROVENANCE.md` and `.claude/skills/LICENSE.pstack`. Preserve the project domain skills; do not install every upstream command or add process ceremony to routine customer replies.
